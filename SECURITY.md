# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities in a public issue or pull request.

Use the repository's **Security** tab to submit a private vulnerability report if private vulnerability reporting is enabled. Otherwise, contact the repository maintainers privately through GitHub and ask for a secure reporting channel. Include the affected area, impact, reproduction details, and any relevant logs with secrets removed.

Do not include real API keys, access tokens, personal data, or other credentials in a report. Revoke any credential that may have been exposed.

## Scope and response

Reports concerning the web application, voting integration, repository data pipeline, and project configuration are in scope. Maintainers will assess reports and coordinate a fix and disclosure when appropriate. No response-time or support guarantee is provided.

## Supported versions

Security fixes are generally made against the latest version on the default branch. Older releases are not guaranteed to receive fixes.
